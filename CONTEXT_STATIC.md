# Постоянный контекст проекта

Читайте этот файл вместе с `CONTEXT_DYNAMIC.md` перед продолжением работы.
Это переносимая память в репозитории, а не зависимость от истории чата.
Проверяйте описанные факты по исходникам; обновляйте этот файл при изменении архитектуры.

## Назначение и требования

Контроллер Wi-Fi камеры DiCam880: просмотр видео, Record/Stop, состояние записи,
обнаружение потери связи и восстановление видео. Камера обычно имеет IP
`192.168.1.1`, PTP/IP порт `15740`, RTSP порт `554`.
RTSP URL: `rtsp://192.168.1.1:554/MJPG?W=720&H=400&Q=50&BR=5000000`.
Несмотря на имя MJPG, камера может передавать H.264.

- `webui/` — исходная рабочая реализация на Python.
- `go/` — самостоятельный HTTP-сервер и контроллер на Go, HTML встроен через go:embed.
- `android/` — самостоятельное приложение Java/LibVLC, напрямую подключается к камере.
  Промежуточный Go/Python-сервер для Android не нужен и пользователем отвергнут.
- Точное отображаемое имя Android: **Digma DiCam Contoller** (сохранить написание).
- В интерфейсе ошибка недоступного сервера должна называться `Server is down`.

## Go и нативное видео

Go >= 1.24, cgo и C11. FFmpeg 8.0.3 статически линкуется через pkg-config.
Пользователю готового приложения не требуется устанавливать FFmpeg или Python.
На macOS/Linux мониторинг вызывает системный `ping`. На Windows используется
`IcmpSendEcho2Ex` (IPv4, source bind, timeout до 900 мс; внешний ping не нужен).

Важные файлы:

- `go/main.go`: CLI, запуск HTTP и обработка завершения.
- `go/worker.go`: мониторинг ICMP, переподключение, состояние камеры.
- `go/ping_unix.go`, `go/ping_windows.go`: платформенные реализации ICMP.
- `go/ptp.go`: PTP/IP и команды камеры.
- `go/ffmpeg_native.go`, `ffmpeg_bridge.c`, `ffmpeg_bridge.h`: cgo и видео.
- `go/scripts/build-ffmpeg.sh`: загрузка, проверка SHA-256 и статическая сборка FFmpeg.
- `go/scripts/go.sh`, `pkg-config-static.sh`: окружение cgo и статическая линковка.
- `go/scripts/windows.sh`, `pkg-config-static-windows.c`: Git Bash/MinGW-w64
  и нативная обёртка pkg-config для Windows Go.
- `go/scripts/check-linkage.sh`: проверка отсутствия динамических FFmpeg-зависимостей.
- `go/third_party/ffmpeg/`: сведения о лицензии и распространении.

Исходники FFmpeg: https://ffmpeg.org/releases/ffmpeg-8.0.3.tar.xz
SHA-256: `6136812ea6d4e68bdba27e33c2a94382711cdf4f8602ffef056ff792bd6f9818`.
Сохранять минимальную конфигурацию из скрипта, без GPL/nonfree и случайных внешних кодеков.
При подготовке публичного пакета следовать `go/third_party/ffmpeg/NOTICE.md`:
включить лицензии, соответствующие исходники и материалы для пересборки/перелинковки.

CLI по умолчанию: `--camera 192.168.1.1 --bind 192.168.1.10 --host 127.0.0.1 --port 5000`.
`--bind` — локальный IP интерфейса для PTP/ping, не HTTP listening address.
`--host` и `--port` задают HTTP. RTSP использует маршрутизацию ОС.
После успешного HTTP-ответа Go открывает браузер по умолчанию один раз.
`--no-browser` отключает это поведение. Для wildcard host открывается loopback.
Ошибка открытия браузера выводится в лог и не останавливает сервер.
`--bind ""` отключает привязку источника. Не назначать чужой/несуществующий IP.
USB/V4L2 пока поддерживается только на Linux; Windows-задача относится к Wi-Fi.

## Сборка и артефакты

На поддерживаемой macOS/Linux из `go/`: `make build`, `make test`, `make vet`.
На Windows x64 из корня: Git Bash запускает `go/scripts/windows.sh build test vet`;
нужны Windows Go и MinGW-w64. Точные команды и проверенные версии — в `go/README.md`.
Тесты Go используют настоящие библиотеки FFmpeg; `CGO_ENABLED=0` не решение.
Кеши и нативные зависимости — `go/.deps/`, не переносить их между ОС.

Готовые артефакты храним в `dist/<tag>/`, например `dist/v0.2.1/`.
Последнее требование пользователя: в `dist/v0.2.1/` оставлять только три бинарника
(Windows EXE, macOS ARM64, Android APK) и их `SHA256SUMS`. Архивы, исходники,
README и служебные файлы из этой папки удалены. Расширенную упаковку, описанную
ниже, выполнять только по отдельному запросу, не восстанавливать её автоматически.
Имена: `dicam-controller-v<version>-<os>-<arch>`; для Windows добавить `.exe`.
Android: `dicam-controller-v<version>-android-universal-debug.apk` для debug-сборки.
Локальные desktop-пакеты: macOS `.tar.gz` и Windows `.zip`, с инструкцией запуска,
лицензиями и исходниками для пересборки; рядом `SHA256SUMS`.
По просьбе пользователя архив исходников FFmpeg не вкладывать в desktop-пакеты:
он хранится отдельным файлом рядом с ними. Для запуска приложения он не нужен.
Упаковка имеющихся проверенных бинарников: `python go/scripts/package-release.py --version v0.2.1`.
По уточнению пользователя этот релиз опубликован только локально. GitHub Release
выполнять лишь по отдельному явному запросу. Готовые файлы не коммитятся в Git.
`dist/` уже игнорируется. Исходники, скрипты и Gradle Wrapper должны отслеживаться.
Постоянный Android signing key хранится отдельно от Git.

## Работа с камерой

Не запускать одновременно несколько контроллеров одной камеры.
После повторных подключений камера может зависнуть до извлечения аккумулятора.
Не проводить бесконечные циклы реконнекта для диагностики: остановить контроллер,
зафиксировать проблему, согласовать с пользователем дальнейший физический тест.
Сначала локальные тесты и проверка сборки, затем реальная камера.
Не менять VPN/защитные настройки телефона без явного согласия.
