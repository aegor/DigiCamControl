## Назначение и требования

Контроллер Wi-Fi камеры DiCam880: просмотр видео, Record/Stop, состояние записи,
обнаружение потери связи и восстановление видео. Камера обычно имеет IP
`192.168.1.1`, PTP/IP порт `15740`, RTSP порт `554`.
RTSP URL: `rtsp://192.168.1.1:554/MJPG?W=720&H=400&Q=50&BR=5000000`.
Несмотря на имя MJPG, камера может передавать H.264.

- `webui/` — исходная рабочая реализация на Python.
- `go/` — самостоятельный HTTP-сервер и контроллер на Go, HTML встроен через go:embed.
- `electron/` — десктопный интерфейс со встроенным дочерним Go/FFmpeg-движком.
- `android/` — самостоятельное приложение Java/LibVLC, напрямую подключается к камере.
  Промежуточный Go/Python-сервер для Android не нужен и пользователем отвергнут.
- Точное отображаемое имя Android: **Digma DiCam Contoller** (сохранить написание).
- В существующем Go/Python веб-интерфейсе ошибка недоступного сервера — `Server is down`.
  Electron использует русские сообщения и автоматически перезапускает недоступный движок.

## Go и нативное видео

Go >= 1.24, cgo и C11. FFmpeg 8.0.3 статически линкуется через pkg-config.
Пользователю готового приложения не требуется устанавливать FFmpeg или Python.
На macOS/Linux мониторинг вызывает системный `ping`. На Windows используется
`IcmpSendEcho2Ex` (IPv4, source bind, timeout до 900 мс; внешний ping не нужен).

Важные файлы:

- `go/main.go`: CLI, запуск HTTP и обработка завершения.
- `go/worker.go`: мониторинг ICMP, переподключение, состояние камеры.
- `go/ping_unix.go`, `go/ping_windows.go`: платформенные реализации ICMP.
- `go/ptp.go`: PTP/IP и команды камеры.
- `go/ffmpeg_native.go`, `ffmpeg_bridge.c`, `ffmpeg_bridge.h`: cgo и видео.
- `go/scripts/build-env.sh`: общий выбор платформы, путей и отпечатка компилятора/SDK/флагов.
- `go/scripts/build-ffmpeg.sh`: загрузка, проверка SHA-256 и статическая сборка FFmpeg.
- `go/scripts/go.sh`, `pkg-config-static.sh`: окружение cgo и статическая линковка.
- `go/scripts/windows.sh`, `pkg-config-static-windows.c`: Git Bash/MinGW-w64
  и нативная обёртка pkg-config для Windows Go.
- `go/scripts/check-linkage.sh`: проверка отсутствия динамических FFmpeg-зависимостей.
- `go/third_party/ffmpeg/`: сведения о лицензии и распространении.

Исходники FFmpeg: https://ffmpeg.org/releases/ffmpeg-8.0.3.tar.xz
SHA-256: `6136812ea6d4e68bdba27e33c2a94382711cdf4f8602ffef056ff792bd6f9818`.
Сохранять минимальную конфигурацию из скрипта, без GPL/nonfree и случайных внешних кодеков.
При подготовке публичного пакета следовать `go/third_party/ffmpeg/NOTICE.md`:
включить лицензии, соответствующие исходники и материалы для пересборки/перелинковки.

CLI по умолчанию: `--camera 192.168.1.1 --bind 192.168.1.10 --host 127.0.0.1 --port 5000`.
`--bind` — локальный IP интерфейса для PTP/ping, не HTTP listening address.
`--host` и `--port` задают HTTP. RTSP использует маршрутизацию ОС.
После успешного HTTP-ответа Go открывает браузер по умолчанию один раз.
`--no-browser` отключает это поведение. Для wildcard host открывается loopback.
Ошибка открытия браузера выводится в лог и не останавливает сервер.
`--bind ""` отключает привязку источника. Не назначать чужой/несуществующий IP.
USB/V4L2 пока поддерживается только на Linux; Windows-задача относится к Wi-Fi.

## Изолированная сборка Electron

Каноническая инструкция — [electron/README.md](electron/README.md).
Команды одинаковы для отдельных рабочих копий macOS и Windows x64:

```text
cd electron
node scripts/build.cjs install
npm run backend
npm test
npm run test:go
npm run vet:go
npm run test:smoke
npm run pack
npm run dist
```

- `install` выполняет `npm ci` по `package-lock.json` с платформенным кешем;
  `npm run setup` — тот же вызов. Не переносить `node_modules` между ОС/архитектурами.
- `scripts/layout.cjs` и `build.cjs` задают `.cache/<target>/` для npm, Electron,
  electron-builder, Go build/modules и native FFmpeg. Target: `darwin-arm64`,
  `darwin-x64`, `win32-x64`, `linux-x64`, `linux-arm64`; Windows ARM64 не поддержан.
- Помимо переменных `ELECTRON_CACHE`/`electron_config_cache`, упаковщик получает
  **явный `electronDownload.cache`**. Одной переменной окружения для нашей версии
  electron-builder недостаточно. `npm run paths` показывает действующие пути.
- Массивы `extraResources`, `files` и targets хранить только в `package.json`:
  electron-builder сам читает его и объединяет массивы с overrides. Повторная
  передача ресурсов из build.cjs вызывает двойное копирование и Windows `EBUSY`.
- Движок: `.cache/<target>/bin/dicam` или `dicam.exe`. Ресурсы:
  `electron/resources/<target>/`. Подготовка очищает только каталог текущей цели.
- Проверять реальный Mach-O/PE/ELF, архитектуру, `--desktop`, SHA-256 и manifest;
  `platform.json` сам по себе не подтверждает платформу. Отвергать чужой node_modules.
- FFmpeg-кеш дополнительно разделён по отпечатку компилятора, SDK, флагов и рецептов.
  Обычная Go-сборка использует `go/.deps/<GOOS>-<GOARCH>/`; Electron передаёт
  `DICAM_NATIVE_CACHE=.cache/<target>/native` и собственные GOCACHE/GOMODCACHE.
- Windows: Node.js x64, Go x64, Git for Windows и MinGW-w64/w64devkit.
  Не использовать WSL Bash. Нестандартный Git Bash задаётся `DICAM_GIT_BASH`,
  MinGW — `DICAM_MINGW_BIN`; локальный Go ищется в
  `go/.deps/toolchain/windows-amd64/go/bin`. Пути сборки FFmpeg — без пробелов.
- Собирать нативно на целевой ОС/архитектуре. `CGO_ENABLED=0` не заменяет FFmpeg.
- Старые общие `electron/resources`, `electron/release/mac-arm64`, `go/dicam` и
  старые кеши не подхватываются автоматически. Не удалять их без необходимости.

## Упаковка и проверки артефактов

`npm run pack` создаёт приложение в `electron/release/<target>/`.
macOS ARM64: `electron/release/darwin-arm64/mac-arm64/DiCam Controller.app`.
Windows x64: `electron/release/win32-x64/win-unpacked/`.
`npm run dist` создаёт DMG/NSIS EXE/AppImage и копирует только установщик с отдельным
`.sha256` в корневой `dist/`; blockmap/YAML остаются в платформенной release-папке.
`npm run dmg:arm64` упаковывает уже собранный macOS ARM64 `.app`.

**DMG:** `--prepackaged` должен указывать на **сам `.app`**, не его родительскую
папку. Иначе получается `.app/.app/Contents`, и Finder рисует перечёркнутый значок.
Проверки: SHA-256, целостность DMG, `Contents/Info.plist`, архитектура и
`codesign --verify --deep --strict` приложения внутри свежесмонтированного образа.
Одной `hdiutil verify` недостаточно. При замене образа не проверять старый том из кеша.

**macOS UUID:** stock Electron и приложения на его основе могут иметь одинаковый
LC_UUID. `scripts/mac-identity.cjs` назначает собственные детерминированные UUID
launcher/helper/Go **до подписи**. Не убирать этот hook. Сборка локально подписана
ad-hoc; Developer ID, notarization и автоматическое обновление не настроены.
Разрешение локальной сети для `Electron.app` не гарантирует доступ DiCam;
терминальный запуск также не доказывает доступ GUI-приложения. При сетевой ошибке
не объявлять отказ разрешения доказанным без дополнительной диагностики.

Electron-пакеты включают лицензии, Go-исходники/скрипты и архив FFmpeg для
перелинковки. Старое требование держать архив отдельно относилось к standalone
релизу v0.2.1, а не к текущему Electron-пакету. Следовать `go/third_party/ffmpeg/NOTICE.md`.
Старый `go/scripts/package-release.py` — отдельный workflow для Go/Android;
не запускать его автоматически при выпуске Electron. GitHub Release — только
по отдельному запросу. Установщики и все файлы `dist/` в Git не добавлять.

## Поведение Electron и проверка интерфейса

Автоподключение к сохранённым камерам при старте; по умолчанию камера `192.168.1.1`,
локальный bind пустой (маршрутизация ОС). Source bind остаётся доступным для отдельного
адаптера, назначать только реально существующий локальный IP. Go CLI сохраняет
старый default `192.168.1.10`. При падении движка Electron повторяет запуск через 5 с.
`--desktop --port 0` запускает Go на loopback, сообщает `DICAM_READY` и завершает
процесс по EOF stdin; браузер в этом режиме не открывается.

Record/Stop могут отвечать несколько секунд. Показывать «Запускаем…», «Идёт запись»,
«Останавливаем…», «Запись остановлена» и REC; обновлять статус после ответа команды.
Кнопка «Настройки» красная при открытой панели (`aria-expanded=true`).
Для перезапуска дождаться завершения старого процесса **до** `open`, затем проверить,
что запустились и приложение, и движок. Одного успешного выхода команды `open` мало.

## Работа с камерой

Не запускать одновременно несколько контроллеров одной камеры.
После повторных подключений камера может зависнуть до извлечения аккумулятора.
Не проводить бесконечные циклы реконнекта для диагностики: остановить контроллер,
зафиксировать проблему, согласовать с пользователем дальнейший физический тест.
Сначала локальные тесты и проверка сборки, затем реальная камера.
Не менять VPN/защитные настройки телефона без явного согласия.
