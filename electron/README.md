# DiCam Controller — Electron

Десктопное приложение для Wi-Fi камер DiCam/iCatch. Интерфейс Electron и встроенный
Go-движок используют протокол и поведение существующих Python/Go-версий. Python,
браузер и внешняя программа FFmpeg для запуска собранного приложения не нужны.
Это Electron-интерфейс с отдельным нативным Go-процессом, а не перенос PTP в JavaScript.

## Подготовка и запуск

Один репозиторий, но **отдельная рабочая копия на каждой ОС**. Не открывайте одну
общую папку одновременно из macOS и Windows/VM: `node_modules` не переносим.
Версии npm-зависимостей фиксирует общий `package-lock.json`.

На macOS/Linux нужны Node.js 22+, npm и инструменты [Go/FFmpeg](../go/README.md).
Из корня репозитория:

```bash
cd electron
node scripts/build.cjs install
npm run backend
npm start
```

`install` выполняет `npm ci` с кешем текущей платформы. `npm run setup` — тот же
вызов. Не используйте системный `npm ci` для воспроизводимой изоляции кешей:
сборочная обёртка задаёт все пути до установки зависимостей. После смены ОС или
архитектуры сборка отвергает чужой `node_modules` и требует повторной установки.

На **Windows x64**, в отдельном клоне, например `C:\src\DigiCamControl`, нужны:
Node.js x64, Go x64, Git for Windows, w64devkit/MinGW с make и pkg-config.
Запускайте те же команды в PowerShell. Обёртка выбирает Git Bash из стандартной
установки; WSL Bash не используется. Нестандартные пути задаются только для сессии:

```powershell
$env:DICAM_GIT_BASH = 'C:\Tools\Git\bin\bash.exe'
$env:DICAM_MINGW_BIN = '/c/w64devkit/bin'
cd electron
node scripts/build.cjs install
npm run backend
npm run pack
npm run dist
```

Исходники FFmpeg и каталог сборки должны находиться по пути без пробелов.
Если Go не установлен в PATH, Windows-обёртка также ищет его в
`go/.deps/toolchain/windows-amd64/go/bin`.

`npm run backend` собирает движок в `.cache/<target>/bin/`, проверяет формат и
архитектуру, наличие `--desktop`, затем подготавливает `electron/resources/<target>/`.
`npm run prepare:backend` повторяет только проверку и копирование. Для собственного
бинарника можно задать `DICAM_BACKEND`: он также проверяется. В локальном кеше должен
присутствовать проверенный архив исходников FFmpeg для включения в пакет.
Старые бинарники `dist/v0.2.1` без `--desktop` не подходят.

В окне укажите IP камеры (по умолчанию `192.168.1.1`) — подключение запускается автоматически. Кнопка **Подключить** применяет изменённые настройки.
Локальный IP по умолчанию пустой: используется маршрутизация ОС. При отдельном
адаптере можно указать `192.168.1.10`, если этот адрес назначен его интерфейсу.
Приложение не меняет настройки Wi-Fi. Другой контроллер камеры следует закрыть:
прошивка может поддерживать только одну PTP-сессию.

## Возможности

- Несколько камер, масштабируемое превью, FPS, модель/прошивка и ошибки связи.
- Record / Stop, Burst 1 / 3 / 5 секунд с прогрессом.
- Восстановление PTP и видео после возвращения камеры в сеть.
- Сохранение настроек в `settings.json` внутри Electron `userData`.
- Выбор папки записей системным диалогом и открытие в файловом менеджере.
- Wi-Fi запись на SD-карту камеры; USB MP4 — в выбранную папку.
- USB через V4L2 только на Linux. На macOS/Windows поддерживаются Wi-Fi камеры.
- При выходе и смене настроек приложение останавливает обнаруженную запись.
  Если остановку нельзя подтвердить, выход требует решения пользователя.
  Аварийное завершение приложения не гарантирует остановку Wi-Fi записи.

При запуске приложение автоматически подключается к сохранённым камерам (при первом
запуске — к `192.168.1.1`). Камеры автоматически переподключаются, пока движок работает;
при сбое самого движка приложение повторяет запуск через 5 секунд. Кнопка
**Подключить** позволяет применить изменённые настройки вручную.

На macOS разрешите DiCam Controller доступ в **Конфиденциальность и безопасность →
Локальная сеть**. Доступность камеры из Terminal не означает, что доступ разрешён
приложению: macOS учитывает разрешение приложения и для его дочернего Go-процесса.
При сетевой ошибке интерфейс предлагает открыть соответствующие настройки.
См. [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).

## Изоляция сборок

```text
.cache/
  darwin-arm64/          # macOS Apple Silicon
  win32-x64/            # Windows x64
    npm/
    electron/
    electron-builder/
    go/build/
    go/mod/
    native/             # FFmpeg: downloads, source, build, libraries
    bin/dicam.exe

electron/
  node_modules/         # только для ОС текущей рабочей копии
  resources/<target>/   # только один проверенный движок и его исходники
  release/<target>/     # папки приложений, установщики, служебные файлы

dist/                   # готовые установщики и их .sha256
```

Обёртка задаёт `npm_config_cache`, `ELECTRON_CACHE`, `electron_config_cache`,
`ELECTRON_BUILDER_CACHE`, `GOCACHE`, `GOMODCACHE`, `DICAM_NATIVE_CACHE`.
`npm run paths` показывает фактические пути. На Windows идентификатор Electron —
`win32-x64`, соответствующие Go OS/arch — `windows/amd64`.

Каталоги библиотек FFmpeg дополнительно содержат отпечаток компилятора, SDK,
флагов и скриптов сборки. После изменения этих входов старые библиотеки не
используются. Кеши не нужно переносить между машинами.

Подготовка ресурсов пересоздаёт только текущий целевой каталог. Перед упаковкой
проверяются настоящий формат Mach-O/PE/ELF, архитектура и SHA-256 бинарника.
`platform.json` сам по себе не считается доказательством совместимости.
Внутри готового приложения этот каталог называется `backend` на всех ОС.

Старые `go/.deps/ffmpeg-*`, общий `electron/resources/` и старые папки
`electron/release/mac-arm64/` автоматически не удаляются. Новые команды их не
используют. Старый `go/dicam` также не подхватывается неявно.

## Упаковка

```bash
npm run pack       # native .app / win-unpacked / linux-unpacked
npm run dist       # native DMG / NSIS EXE / AppImage, копия в ../dist/
npm run dmg:arm64  # macOS ARM64: упаковать уже готовый .app в DMG
```

Для macOS ARM64 приложение лежит в
`electron/release/darwin-arm64/mac-arm64/DiCam Controller.app`.
Для Windows x64 — в `electron/release/win32-x64/win-unpacked/`.
Готовые установщики получают имена вида:

- `dist/DiCam-Controller-0.1.0-macos-arm64.dmg`
- `dist/DiCam-Controller-0.1.0-windows-x64-setup.exe`

Рядом создаётся отдельный `.sha256`; служебные blockmap/YAML остаются в
`release/<target>/`. Сборка не публикует файлы в сеть.

`--prepackaged` на macOS должен указывать на сам пакет `.app`, а не его родителя.
`dmg:arm64` проверяет наличие `Contents/Info.plist`, чтобы исключить вложенный `.app`.
После выпуска образа проверяйте структуру и подпись приложения внутри DMG.

Собирайте на целевой ОС и архитектуре: Go/cgo/FFmpeg не настроены для
кросс-компиляции. Поддержаны macOS ARM64/x64, Windows x64, Linux x64/ARM64.
Windows ARM64 пока явно отклоняется. Итоговому приложению не нужны Node.js, npm,
Go или Python.
На macOS/Linux нужен системный `ping`. Подпись разработчика, notarization и
автообновление не настроены; локальная macOS-сборка использует ad-hoc подпись.
Не публикуйте её как подписанный релиз.

В ресурсы приложения включаются исходники Go, скрипты сборки и архив FFmpeg
для повторной линковки. Лицензии и сведения о повторной линковке берутся из
[`go/third_party/ffmpeg`](../go/third_party/ffmpeg/NOTICE.md).

## Проверки

```bash
npm test
npm run test:smoke  # открывает окно, использует 127.0.0.1 вместо камеры
npm run test:go     # Go -race, тот же платформенный кеш, включая Windows
npm run vet:go
```

Node-тесты проверяют настройки и реальный Go-движок: свободный порт, API, ошибки
команд, перезапуск и завершение по EOF stdin. Интеграционный тест пропускается,
если `resources/<target>/dicam` (на Windows `dicam.exe`) ещё не подготовлен. Smoke-тест проверяет настоящее окно,
preload/IPC, форму подключения и отсутствие Node.js в renderer; снимок —
`release/<target>/smoke.png`. Нужны графическая сессия и разрешение на локальные TCP-порты.
Эти проверки не заменяют тестирование видео и записи с физической камерой.

## Устройство

- `src/main.cjs` — окно, настройки, системные диалоги, проверка IPC, выход.
- `src/backend.cjs` — запуск Go, ожидание готовности, HTTP API и завершение.
- `src/preload.cjs` — ограниченный API для renderer.
- `src/renderer.js`, `index.html`, `styles.css` — интерфейс.
- `scripts/build.cjs`, `layout.cjs` — единые команды и изоляция кешей.
- `scripts/prepare-backend.cjs`, `binary.cjs` — сборка, проверка и копирование движка.
- `scripts/before-pack.cjs` — проверка ресурсов перед упаковкой.

Go-флаг `--desktop --port 0` принудительно использует loopback, отключает браузер,
пишет `DICAM_READY <url>` в stdout и завершает сервер по EOF stdin. Это позволяет
Electron управлять процессом и на Windows, без Unix-сигналов. Обычный CLI Go
сохраняет прежнее поведение. Порт назначается ОС без предварительного резервирования.

Renderer работает с `sandbox`, `contextIsolation`, без Node.js и с CSP.
Команды идут через ограниченный IPC, а MJPEG — непосредственно с loopback.
Настройки из интерфейса валидируются в главном процессе; оболочка для запуска
Go не используется. Подход следует [рекомендациям Electron по безопасности](https://www.electronjs.org/docs/latest/tutorial/security).

### Идентичность macOS-сборки

`afterPack` назначает launcher, вспомогательным приложениям Electron и встроенному
Go-движку собственные детерминированные Mach-O UUID, затем electron-builder заново
подписывает приложение. Это устраняет совпадение UUID с исходным `Electron.app`
и самостоятельным Go CLI. Системные разрешения не меняются: при первом обращении
к камере macOS может запросить доступ именно для DiCam Controller.
Причина: [Apple TN3178](https://developer.apple.com/documentation/technotes/tn3178-checking-for-and-resolving-build-uuid-problems).
