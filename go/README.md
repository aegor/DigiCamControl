# DiCam Controller — Go + FFmpeg libraries

Самостоятельный аналог `webui`. HTTP-сервер, PTP/IP-клиент и мониторинг написаны
на Go. Видео обрабатывается внутри приложения через cgo и библиотеки FFmpeg:
`libavformat`, `libavcodec`, `libavdevice`, `libswscale`, `libavutil`.

**Для запуска готового `dicam` не нужны Python, OpenCV, программа `ffmpeg` или
отдельно установленные библиотеки FFmpeg.** FFmpeg статически включён в бинарный
файл; HTML также встроен через `go:embed`. Приложение можно запускать из любой
папки. Системные библиотеки ОС продолжают использоваться обычным способом.

## Запуск готового приложения

```bash
./dicam --port 5001
```

После запуска сервера браузер по умолчанию автоматически откроет интерфейс
(в этом примере <http://127.0.0.1:5001/>). Флаг `--no-browser` отключает открытие.
Открытие происходит один раз после успешного HTTP-ответа, без ожидания камеры.
Для `--host 0.0.0.0` используется `127.0.0.1`, для `--host ::` — `::1`.
Если браузер открыть не удалось, сервер продолжит работать и выведет ссылку
для ручного открытия. На Windows используется системная ассоциация HTTP,
на macOS — `open`, на Linux — `xdg-open` (нужна графическая сессия).
Без `--camera` и `--usb` используется
камера `192.168.1.1`. По умолчанию `--bind 192.168.1.10`, `--host 127.0.0.1`,
`--port 5000`. На macOS порт 5000 может быть занят системной службой.

На macOS/Linux нужна системная команда `ping` с разрешением отправлять ICMP.
На Windows используется `IcmpSendEcho2Ex`: IPv4, source bind, timeout до 900 мс
(также предел задержки отмены выполняющегося запроса). Wi-Fi камеры поддерживаются
на macOS, Linux и Windows x64; USB — только на Linux через V4L2 (`/dev/videoN`).

```bash
# Доступ из локальной сети
./dicam --host 0.0.0.0 --port 5001

# Несколько Wi-Fi камер, маршрутизация без привязки к source IP
./dicam --camera 192.168.50.11 --camera 192.168.50.12 --bind "" --port 5001

# USB на Linux; --camera и --usb можно сочетать
./dicam --usb /dev/video0 --record-dir ./recordings --port 5001
./dicam --usb auto --port 5001

./dicam --help
```

Параметр `--ffmpeg` удалён: внешний исполняемый файл больше не используется.
Перед запуском остановите другой контроллер этой же камеры: прошивка может
сохранять единственную PTP-сессию. `--bind` задаёт source IP для PTP/IP и ping;
RTSP использует маршрутизацию ОС. Локальный IP должен быть назначен интерфейсу.

## Сборка из исходников

Только на машине сборки нужны:

- Go 1.24 или новее и C-компилятор (Clang/GCC, поддержка C11).
- `make`, `pkg-config`, `curl`, `tar` с поддержкой xz и `shasum`/`sha256sum`.
- На macOS — Command Line Tools; на Linux — обычный комплект инструментов C.
- Интернет при первом скачивании исходников FFmpeg.

Из корня репозитория:

```bash
cd go
make build
./dicam --port 5001
```

`make build` скачивает **FFmpeg 8.0.3** с официального сайта, проверяет
зафиксированный SHA-256, собирает минимальные статические библиотеки и затем
`dicam`. Зависимости размещаются в `go/.deps/<GOOS>-<GOARCH>/`; каталоги FFmpeg
включают отпечаток компилятора, SDK, флагов и скриптов. В Electron-сборке
`DICAM_NATIVE_CACHE` перенаправляет их в `.cache/<target>/native/`; системная установка
FFmpeg не производится. Первая сборка занимает несколько минут, последующие
используют уже собранные библиотеки. Число параллельных задач можно изменить:

```bash
DICAM_BUILD_JOBS=8 make build
```

Собирайте на целевой ОС и архитектуре. Скрипт не настраивает кросс-компиляцию
cgo/FFmpeg. Бинарник macOS ARM64 нельзя запускать на Linux или macOS Intel.

После сборки `check-linkage.sh` проверяет через `otool -L`/`ldd`, что у бинарника
нет динамических зависимостей от FFmpeg. Для повторной сборки только Go-кода:

```bash
./scripts/go.sh build -o dicam .
make check-linkage
```

Обёртка `scripts/go.sh` настраивает cgo и `pkg-config --static` на локальные
библиотеки. Обычный `go build` без этих настроек не предназначен для этой сборки.
HTML встроен в бинарный файл: после его изменения нужно пересобрать приложение.

## Сборка Windows x64

Нужны Windows Go >= 1.24, Git Bash и MinGW-w64 GCC с C11, make и pkg-config.
В этой рабочей копии используется w64devkit в `C:/w64devkit/bin`.
Go можно установить отдельно либо распаковать официальный Windows amd64 ZIP
в `go/.deps/toolchain/windows-amd64/` (получится `toolchain/windows-amd64/go/bin/go.exe`), проверив SHA-256
по https://go.dev/dl/. Системные настройки PATH менять не требуется.

Из корня репозитория в PowerShell:

```powershell
& 'C:/Program Files/Git/bin/bash.exe' go/scripts/windows.sh build
& 'C:/Program Files/Git/bin/bash.exe' go/scripts/windows.sh test
& 'C:/Program Files/Git/bin/bash.exe' go/scripts/windows.sh vet
.\go\dicam.exe --help
```

Укажите фактический путь к Git Bash (на этой машине `C:/pf/Git/bin/bash.exe`).
Другую папку MinGW можно задать переменной `DICAM_MINGW_BIN` в формате Git Bash,
например `/c/tools/w64devkit/bin`. Не используйте одноимённый `bash.exe` из
w64devkit: сборке нужен настоящий Bash с поддержкой массивов.
Путь к репозиторию должен быть без пробелов: это ограничение out-of-tree configure
FFmpeg. Обёртка pkg-config отдельно проверена с пробелами в путях к executable.

`windows.sh` задаёт инструменты только для текущего процесса. FFmpeg собирается
из того же проверенного архива в отдельные каталоги Windows; Mac-кеш не используется.
Нативная C-обёртка pkg-config добавляет `--static`, в том числе для u-config,
и работает при вызове из Windows Go. Линковка `-static` включает runtime GCC;
`objdump -p` проверяет PE imports по списку системных DLL, отклоняя FFmpeg и
посторонние runtime DLL. Результат: `go/dicam.exe`.

Проверка ICMP использует только loopback. Остальные тесты используют локальные
имитаторы; они не доказывают работу видео и команд с физической камерой.
Дополнительная проверка готового файла (Python нужен только для этой проверки):

```powershell
python go/scripts/smoke-windows.py go/dicam.exe
```

Она запускает контроллер с `--no-browser`, адресом камеры `127.0.0.1`, пустым `PATH`, проверяет
HTTP/UI и отправляет Ctrl+C в отдельную скрытую консоль процесса.

Проверено 2026-10-25: Go 1.27.3, GCC 14.2.0, GNU Make 4.4.1,
u-config 0.33.1, FFmpeg 8.0.3 на Windows x64. Все 29 Go-тестов прошли с `-race`,
`vet`, UI-тесты и проверка запуска/Ctrl+C также прошли. PE imports содержат только
`bcrypt.dll`, `IPHLPAPI.DLL`, `KERNEL32.dll`, `msvcrt.dll`, `ole32.dll`,
`SHELL32.dll`, `WS2_32.dll`. Автооткрытие проверено через подставной обработчик
запуска браузера; реальное окно в автоматических тестах не открывается.
Проверенный файл скопирован в
`dist/v0.2.1/dicam-controller-v0.2.1-windows-amd64.exe`, сумма — в `SHA256SUMS`
рядом с ним. Физическая камера на Windows пока не проверена.
Существующий macOS-бинарник в dist не пересобирался и ещё не содержит автооткрытие
браузера; для него нужна новая сборка на macOS из обновлённых исходников.

## Локальный релиз

По запросу пользователя в `dist/v0.2.1/` оставлены только Windows EXE, macOS
ARM64, Android APK и `SHA256SUMS` с тремя суммами.
Для отдельного запроса на расширенную упаковку из корня репозитория:
`python go/scripts/package-release.py --version v0.2.1`.
Скрипт упаковывает проверенные бинарники из `dist/v0.2.1/` в Windows ZIP и macOS
tar.gz, добавляет инструкции, лицензии и исходники Go/Android, обновляет
`SHA256SUMS`. Архив исходников FFmpeg хранится отдельно рядом с desktop-пакетами,
внутрь них не включается и для запуска не нужен. APK остаётся отдельным файлом
с debug-подписью.
Сборка заново и публикация на GitHub не выполняются. Скрипт заново создаёт
дополнительные файлы в папке релиза. Для упаковки нужен Python 3.11 или новее.

## Видео и восстановление связи

- MJPEG-пакеты RTSP/V4L2 передаются браузеру напрямую, без перекодирования.
  Если камера отдаёт H.264 (в том числе по адресу `/MJPG`), библиотека декодирует
  его и формирует JPEG-превью, уменьшая ширину до 1280 пикселей при необходимости.
- USB-запись декодирует JPEG, преобразует цветовой формат и кодирует MPEG-4 в MP4
  через библиотеки. Режим USB: MJPEG 1920×1080 @ 30 fps; устройство должно его
  поддерживать. Запись сохраняется в `~/larkfly_recordings/` или `--record-dir`.
- Очередь записи ограничена; перегрузка кодировщика отображается как ошибка.
  Неуспешный/пустой файл записи удаляется. Stop и штатное завершение дописывают
  очередь кадров и MP4 trailer перед закрытием файла.
- Ping выполняется раз в секунду для каждой Wi-Fi камеры. При потере связи
  внизу появляется `lost connection to camera`, старые кадры сбрасываются на
  сервере, текущая сессия прерывается. После возвращения ping PTP и RTSP
  подключаются заново, число попыток не ограничено.
- Перезапуск RTSP при смене режима записи не закрывает исправное PTP-соединение.
  Record/Stop остаются доступны, пока камера доступна, даже если превью
  переподключается. При потере сети восстанавливаются оба соединения.
- Отмена Go-контекста передаётся FFmpeg через `AVIOInterruptCB` и атомарный флаг
  в C-памяти. Сетевые операции ограничены по времени; при отсутствии кадров
  в течение 8 секунд поток переподключается. V4L2 использует неблокирующее чтение.
- При недоступном HTTP-сервере показывается `Server is down`. После восстановления
  браузер повторно открывает MJPEG даже после перезапуска самого сервера.
- HTTP MJPEG ограничен 15 fps; счётчик FPS показывает частоту кадров от камеры.

Камера должна отвечать на ICMP. После её включения компьютер должен подключиться
к её Wi-Fi; приложение не изменяет сетевые настройки ОС. Возобновляются видео
и управление, а не прерванная запись.

## Управление и API

Сохранены адаптивное видео, Record / Stop, индикатор REC, Burst 1 / 3 / 5 секунд
и его прогресс. Фото отсутствует. Wi-Fi запись выполняется на SD-карту через
PTP-свойство `0xD604`: `17` — старт, `1` — стоп.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Интерфейс |
| GET | `/api/status` | Состояние камер и Burst |
| GET | `/video_feed/0` | MJPEG камеры с индексом 0 |
| POST | `/api/record/start` | Начать запись |
| POST | `/api/record/stop` | Остановить запись и отменить Burst |
| POST | `/api/burst` | JSON `{"duration": 3}`; 1–60 секунд |

Ответы команд содержат `results` для каждой камеры; ошибки видны в интерфейсе.
При активном Burst повторные Burst/Record возвращают 409. Stop отменяет старый
таймер, чтобы он не остановил следующую запись. Некорректный JSON возвращает 400.

Ctrl+C завершает сервер, закрывает подключения и финализирует USB MP4. Wi-Fi
запись на SD-карту следует остановить кнопкой Stop перед выходом: отключение
контроллера само по себе не останавливает запись на камере.

## Проверки

```bash
make test
make vet
# Если установлен Node.js; npm-зависимостей нет
node web/ui_test.cjs
```

Тесты используют реальные статически связанные библиотеки FFmpeg, JPEG-кадры,
созданные средствами Go, и локальные имитаторы TCP/HTTP. Проверяют чтение MJPEG,
создание и повторное открытие MP4, отмену зависших RTSP/видеосоединений, очистку
неуспешной записи, PTP/iCatch, Burst, мониторинг и переподключение. Видеотесты
работают с пустым `PATH`, подтверждая отсутствие запуска `ffmpeg`/`ffprobe`.
Физическая камера не требуется. Для сетевых тестов нужны локальные TCP-порты.

При проверке на реальной камере дождитесь видео, выключите и включите камеру
и её Wi-Fi. Сервер и страницу перезапускать не нужно. Оставьте сервер работающим
после теста, иначе браузер покажет `Server is down`.

## Структура

- `main.go` — CLI и жизненный цикл сервера.
- `ptp.go` — PTP/IP с особенностями iCatch.
- `worker.go` — камеры, мониторинг, восстановление.
- `video.go` — получение кадров и очередь USB-записи.
- `ffmpeg_native.go` — cgo, владение памятью и отмена операций.
- `ffmpeg_bridge.c`, `.h` — C API для ввода, кодирования и MP4.
- `server.go`, `web/index.html` — API и интерфейс.
- `scripts/`, `Makefile` — сборка и проверка статической линковки.
- `third_party/ffmpeg/` — лицензия и сведения о включённой библиотеке.

FFmpeg собран без GPL/nonfree-компонентов. Сведения об исходниках, лицензии
LGPL-2.1-or-later и повторной линковке находятся в
[third_party/ffmpeg/NOTICE.md](third_party/ffmpeg/NOTICE.md).

## Изоляция при сборке Electron

Для Electron используйте команды из [electron/README.md](../electron/README.md).
Они передают отдельный `DICAM_NATIVE_CACHE`, `GOCACHE`, `GOMODCACHE` и путь `BINARY`.
Обычный `make build` по-прежнему создаёт `go/dicam` / `go/dicam.exe`, но кеши
по умолчанию теперь находятся в `go/.deps/<GOOS>-<GOARCH>/`. Старые кеши не удаляются.
Общий `scripts/build-env.sh` выбирает одинаковые библиотеки для FFmpeg и cgo;
новый компилятор, SDK, флаги или рецепт создают новый каталог сборки.
